# 项目检查与验收闭环

本文件是过程检查、最终验收和返工状态的唯一入口。验收对象始终是关闭生成文档后重新打开的最终 DXF；自动检查通过只证明对应数据关系成立，不能代替人工审图、目标 CAD 测试或工程批准。

## 1. 记录和验收文件

每个项目使用同一前缀保存：最终 DXF、图幅评估 JSON、工程图检查记录 JSON、DXF 性能审计 JSON、回读预览 PNG 和项目验收记录 JSON。回读预览只用于验收。

过程记录至少包含源对象/数据、目标视图或图幅位置、检查依据、方法、结果、差异、修复和复查结果。状态只允许 `pass/fail/pending/not_applicable`；待确认项必须说明缺少的输入。

## 3. 自动门禁

`scripts/project_acceptance.py` 汇总检查记录、图幅评估、性能审计、最终 DXF 和回读预览。自动门禁与脚本编号保持一致：

| 编号 | 检查项 | 核心通过条件 |
| --- | --- | --- |
| A01 | 源模型标识与保留 | 当前源文件可追溯且只读保留，并记录有效 SHA-256 |
| A02 | 前视图与绘图坐标基 | 合法 `front_source`、来源、标准相机方法和完整三轴基 |
| A03 | 模型与实例盘点 | 本体存在，声明与逐件实例数量一致 |
| A04 | 压铆识别、分类、分面、位号与轮廓色 | 候选状态闭合且无待确认项；独立审计重新读取与记录哈希一致的当前 STEP/STP，重新识别实例/安装孔，并确认每个卯柱恰有一个唯一关联的非空辅助字符串。字符串任意位置包含一个有效公制 `M…` 螺纹规格即为 `threaded`，不包含即为 `unthreaded`；两类可单独或同时出现。随后独立复算局部板厚、柱身侧露出量、压铆进入背面、柱体自由端及 `H=露出量+局部板厚=|柱端-背面|`，并复算通孔/盲孔拓扑、盲孔深度、完整分类键、规格、安装板外表面、柱身侧/内外延伸、三维锚点和投影纸面坐标；孔型与螺纹需求独立，通盲不同、有/无螺纹不同或螺纹规格不同不得同类，目标视图只取安装板外表面，独立实例集合与记录完全相等，逐件结果与最终 DXF 一致，且无未登记、重复或越界标记；每件 `STUD_OUTLINE` 内外轮廓的中心、直径、类别颜色及 handle 均通过回读核对 |
| A05 | 六视图布局、投影基准与 HLR 完整性 | 六视图齐全、固定第三角法顺序和共同投影基准成立；逐视图完整记录并处理当前 FreeCAD 返回的全部可见/隐藏 HLR 分组，功能性内部轮廓可从源 STEP 追溯到最终 DXF |
| A06 | 图幅终评估 | 指定/选定图幅、最高可行统一比例、边界、碰撞和可读性通过 |
| A07 | 六视图尺寸覆盖、补充视图追溯、孔清单策略、样式与回算 | 六个视图均有尺寸，项目要求的缺项为空，显示值与模型一致；预期尺寸全部为原生 `DIMENSION`，统一使用合格 `DIMSTYLE`、闭合实心箭头和尺寸界线，手工拼接尺寸为零；`feature_annotation_audit.py` 重新读取同一 STEP 和最终 DXF，独立重建的圆孔清单与记录一致，并确认 `annotation_policy=no_automatic_grouped_callout`、`displayed_group_callouts=0` 且图中没有 `FEATURE_CALLOUT` 实体；默认补充视图数为零，确有必要的局部图/剖视/辅助视图必须具备主视图来源范围、观察/剖切方向、成对编号、比例、STEP 特征关联、主视图与补充投影变换及可回读实体 handle，来源边界固定在 `SUPPLEMENTARY_BOUNDARY` 非连续细线层，编号和方向在 `SUPPLEMENTARY_LABEL` 层，两层异于普通投影且实体随层；来源标记 handle 与零件几何/尺寸互斥，实际标签、框线和方向标记集合与登记集合完全一致，任何孤立或未登记标记均失败 |
| A08 | 最终 DXF 文字、说明、表格和标题栏 | `dxf_text_audit.py` 独立审计通过；`NOTES` 图层中的技术要求标题及编号正文与固定标题和五条正文完全一致、顺序正确且没有缺项/重复/多项/改字，同层其他详图标签不参与该集合；使用字体无替换，逐文字清单覆盖全部表格/标题栏文字，字形框位于所属单元格安全区，压线、越格、净距失败和表格线相交数均为零；参考模板要求的六个标题栏合并区齐全且内部网格线为零；默认未注公差区必须保持原表格格式，四个结构表头完整且数量正确，并另外与 Skill 默认 19 项参数内容完全一致且不含“待确认”占位；四个表头不计入 19 项参数；生成器自报结论不能单独通过 |
| A09 | 最终 DXF 回读与一致性 | 文件哈希一致，回读审计错误和修复均为零 |
| A10 | DXF 结构、解析实体与碎片性能 | 无非有限坐标、同层重复投影、可见/隐藏精确重合或项目性能上限失败；直线、圆弧和圆未被无理由离散，连续物理边不由大量微小实体承载；独立性能审计确认可见层为连续线、隐藏层线型已定义且比例有效，并确认无模板覆盖时 `HIDDEN=ACI 8`、`DIMENSION=ACI 2`；模型空间实体、逐尺寸局部覆盖、尺寸匿名块及从两层引用的块内容均继承图层颜色，不得写死白色 |
| A11 | 最终 DXF 回读预览 | 预览来自当前 DXF，文件有效且渲染进程正常退出；可见轮廓连续清晰、隐藏线不是点状碎线、内部功能轮廓无缺失 |

任一自动项为 `fail`，状态固定为 `rework_required`，禁止交付。确认只有漏标时，只补齐可唯一确定的缺失标注并同步生成源和检查记录，已有正确标注保持不变；其他问题在识别、投影、标注、排版或 DXF 生成源中按影响范围修复。修改后重新导出最终 DXF，并重查受影响项目及整图布局、哈希和性能。

### 不可跳过的标注后闭环

每轮标注完成后固定执行：记录当前 STEP SHA-256 → 导出最终 DXF → 关闭生成文档 → 在新进程重新导入当前 STEP → 回读最终 DXF → 文字审计 → STEP 圆孔清单及禁用成组孔标审计 → STEP↔DXF 压铆位置及轮廓色审计 → 性能审计 → 当前 DXF 回读预览 → A01～A11 汇总 → 输入和人工门禁。该完整自动闭环连续执行 `2～3` 遍，默认 `3` 遍；每遍必须创建独立审计和验收文件。A01～A11 必须完整出现且状态只能为 `pass/fail`；自动项不得省略、标为 `not_applicable`、沿用旧轮次结果或因其他项目通过而抵消。

所有独立证据必须属于同一个当前源模型和最终 DXF：孔标审计与压铆审计的 `step_sha256` 必须等于检查记录的 `source_sha256`，文字、孔标和压铆审计的 DXF 路径及 SHA-256 必须匹配，性能报告和预览必须在当前 DXF 生成后重新产生。验收记录用 `closed_loop.independent_step_to_dxf_geometry_verified`、`no_skipped_automatic_checks` 和 `all_independent_artifacts_bound_to_current_dxf` 明确记录这些条件。

连续复核使用 `scripts/closed_loop_recheck.py`。`--runs` 只允许 `2` 或 `3`，未指定时为 `3`。汇总必须满足 `completed_runs=required_runs`、每遍 `pass=true`、`all_runs_same_source_and_dxf=true`、`all_runs_same_inputs=true`；任一遍失败或期间任何 STEP、DXF、检查记录、图幅评估或预览发生变化，连续通过次数归零，修复后从第 1 遍重新开始。重复运行同一汇总程序不代替各遍独立子进程和独立报告。

- `failed_codes` 非空：禁止交付；单纯漏标只补缺失项，其他问题按影响范围修复；作废本轮审计和预览，重新导出最终 DXF 并从第一项重查。
- 无失败但 `pending_codes` 非空：继续取得输入或实际执行人工/目标 CAD 检查；不得宣称全部正确。
- 只有 `drawing_checks_complete=true`：制图检查闭环完成。工程批准仍由 P01 单独控制。

闭环不设置“重试若干次后忽略”的出口。只要存在明确、安全且在任务范围内的修复就继续；缺少设计输入、几何无法唯一判定、外部 CAD 不可用或工具故障无法排除时，停止交付并报告阻塞证据，而不是写入 `pass`。

### 压铆位置专项验收标准

| 检查对象 | 方法 | 通过条件 |
| --- | --- | --- |
| 候选识别 | 检查装配身份、几何和候选状态汇总 | `候选总数 = confirmed + rejected + pending`，正式交付时 `pending=0`；非压铆小零件不得进入 `fasteners` |
| 柱轴与安装孔 | 检查逐件源证据 | 柱轴来自同轴圆柱面并与安装孔同心；不得使用包围盒方向或普通孔替代 |
| 安装总高度 | 独立复算安装孔处局部板厚、柱身侧露出量、压铆进入背面坐标和柱体自由端坐标 | `height_basis=press_in_back_face_to_free_end_includes_local_sheet_thickness`；`height = body_side_exposed_height_mm + local_sheet_thickness_mm = |free_end_coordinate - press_in_back_face_coordinate|`，两式在尺寸容差内一致；不得以独立实体轴向总长代替，也不得直接距离测量后再次加板厚 |
| 卯柱加工属性、孔型与分类 | 核对与源实例唯一关联的非空 3D 辅助字符串；在字符串任意位置解析有效公制螺纹规格；隔离卯柱自身实体，检查两端开口、沿柱轴空腔连续性和封闭孔底；再核对逐件分类键及类别表 | 包含一个有效 `M…` 规格对应 `threaded` 并保存规范化 `thread_designation`，不包含对应 `unthreaded` 且规格为空；空字符串、多个不同螺纹规格、来源冲突或不可唯一关联均为待确认。覆盖数等于已确认实例数即可，全 threaded、全 unthreaded 和混合均通过。`hole_type` 只能为独立确认的 `through/blind`，且不限制 unthreaded 必须为通孔；分类键包含加工孔类型、螺纹规格（如适用）、孔型及适用的盲孔深度，规格与总数一致 |
| 外表面、接触侧与柱身侧 | 对照安装孔所属板件、局部板厚两表面、结构内腔/外部可达关系、压铆实体轴向范围和两侧实际伸出量 | 独立复算安装板外表面及柱身内外延伸状态；目标视图必须与安装板外表面一致，不能与柱身方向机械绑定；不得使用圆柱曲面 Axis 正负、全局坐标正负、模型原点、最近孔口或仅靠整体包围盒推断，证据不足必须 `pending` |
| 六视图二维变换 | 检查 `annotation_validation.per_view_transforms` | 六视图各有唯一变换标识、至少三个不共线校准特征且纸面最大残差不超过位置容差；HLR、锚点、尺寸和视图边界共用该变换 |
| 三维锚点 | 检查逐件 `anchor_kind/anchor_3d` | 锚点是柱轴与安装面或局部板厚中面的交点，不是包围盒中心或实体质心 |
| STEP→DXF 位置 | 用 FreeCAD Python 执行 `stud_annotation_audit.py --step <当前源模型>`；审计脚本在新文档中重新导入 STEP，独立重建实例/高度证据/孔型/分类键/安装孔/安装板外表面/柱身侧/锚点和正投影，并复核与 STEP 哈希绑定的辅助标记证据，再回读最终 DXF | STEP 哈希一致；独立实例集合与记录集合完全相等；逐件局部板厚、柱身侧露出量、压铆进入背面、柱端、安装总高度、辅助标记、加工孔类型、孔型、盲孔深度、分类键、规格、安装孔轴向区间、安装板外表面、柱身侧和三维锚点一致；实际 DXF 锚点与独立投影坐标偏差不超过容差，锚点和位号 handle 唯一且位于由安装板外表面独立推导的目标视图内 |
| 类别色内外轮廓 | 回读逐件 `STUD_OUTLINE` handle、实体中心、半径和显式颜色 | 每件恰有内外两个解析圆轮廓；中心与独立锚点同心，直径与 STEP 复算内外径一致，颜色与类别色一致；缺失、多余、重复或仅文字着色均失败 |
| 多余/错误位号 | 回读 `STUD_ANCHOR/STUD` | 两层实际 handle 集合分别与逐件记录完全相等；未登记或缺失的锚点/位号、重复 handle、来自排除/待确认候选的位号和无压铆视图中的位号均为零 |

工程图检查记录必须提供 `source_sha256`、`fastener_candidate_summary` 和 `annotation_validation`。前者固定包含 `candidate_count/confirmed_count/rejected_count/pending_count`；后者至少包含 `position_tolerance_mm`、`anchor_layer`、`view_bounds_sheet_mm`、六视图 `per_view_transforms`、逐件 `per_item`、`extra_marker_handles`、`duplicate_marker_handles` 和 `pass`。生成器写入的候选、目标视图、期望坐标和 `pass` 不能替代 `stud_annotation_audit.py` 对当前 STEP 与最终 DXF 的独立重建和逐件比较。

### 图线专项验收标准

| 检查对象 | 方法 | 通过条件 |
| --- | --- | --- |
| HLR 分组 | 检查 `projection_validation.per_view` | 六个视图均记录 10 组原始数量、启用组、过滤组和理由；默认启用 `V/VO/H/HO`，额外组有逐特征依据 |
| 可见/隐藏重合 | `dxf_performance_audit.py` 直接读取最终 DXF | `visible_hidden_exact_overlap=0`；局部预览无隐藏虚线覆盖可见实线 |
| 图层、线宽与颜色 | 回读 `VISIBLE/HIDDEN/CENTER/BORDER/DIMENSION` 并执行 `dxf_performance_audit.py` | 线型存在且未替换，线宽满足 `BORDER ≥ VISIBLE > HIDDEN ≥ CENTER > 0`，尺寸线不压过轮廓；无已确认模板覆盖时 `HIDDEN` 为 ACI 8 灰色、`DIMENSION` 为 ACI 2 黄色，两层实体均随层且尺寸样式颜色不写死为 ACI 7，`color_validation.pass=true` |
| 虚线节奏 | 100% 声明比例预览和局部放大 | 线段与间隔清楚，不呈点列，不因碎实体反复重启相位 |
| 解析几何 | 统计实体类型并抽查圆孔、圆弧和直边 | 可解析几何使用 `LINE/ARC/CIRCLE`；无理由离散数量为零，闭合孔槽不断裂 |
| 内部轮廓 | 源 STEP 特征清单对照六视图 | 每个功能孔槽和压铆内外轮廓都有正确的可见或隐藏表达，无漏投、误连或镜像 |
| 预览证据 | `record_projection_review.py` | 预览来自最终 DXF，SHA-256 匹配，检查人和三类缺陷计数齐全且均为零 |

自动结构检查与预览检查必须同时通过。自动检查不能判断的部分重合、视觉节奏和源特征完整性由 M02/M03 关闭；未实际检查时保持 `pending`，不得填零通过。

## 4. 人工、项目输入和批准门禁

- `I01`：材料、表处、图号、版本、日期、数量、公司、签署和项目模板等输入完整性。未注公差在没有覆盖模板时使用 Skill 默认表，不因缺少项目公差输入而改成“待确认”；若声明覆盖默认表，则覆盖模板及数值必须已确认。其他输入缺失时允许审图草稿，但状态保持 `pending`。
- `M01`：设计人员用 STEP 与最终 DXF 核对 FRONT、朝上、镜像、六视图、六个二维变换和至少三个不共线特征；确认不存在几何正确但位号坐标轴旋转/镜像的情况。
- `M02`：逐视图核对尺寸、符号、引线、压铆候选身份、安装板外表面、柱身内外延伸、安装孔处局部板厚、背面到柱端的安装总高度、安装孔锚点、位号、规格、数量、固定技术要求、表格、标题栏及 100%/声明比例纸面效果；确认左下角技术要求标题和五条正文完整且无附加项，无压铆位置没有位号、每个确认实例只在安装板外表面视图出现一次，未注公差不是占位值，隐藏线为灰色且尺寸标注采用独立颜色，并局部放大核对可见轮廓连续性、虚线节奏和内部功能轮廓完整性。若存在局部图、剖视或辅助视图，还须从补充视图编号反查主视图来源范围及方向，再从来源标记正查同编号视图，确认比例、观察关系和 STEP 特征一致；来源框必须呈异色非连续细线，方向箭头与成对编号清晰，不能与普通轮廓混淆；任一方向无法反查或视觉上误认成零件图线即失败。
- `M03`：在指定 CAD 中执行打开、全图、缩放、平移、局部放大、图层切换、打印预览和保存副本；记录软件版本、硬件和打开耗时。
- `P01`：企业授权人员完成工程批准/投产放行；生成程序不得自行设置通过。

人工发现问题同样记为 `fail` 并返回生成源。尚未实际执行的操作必须记为 `pending`，不能根据预览或脚本结果代填 `pass`。

## 5. 返工影响范围

- 改方向或视图变换：重算六视图、六视图校准、压铆分面、全部锚点/位号坐标、尺寸、表格和图幅。
- 改几何识别或分类：重查候选状态、装配身份、安装孔、柱轴、逐件映射、位号、类别表、六侧和尺寸覆盖。
- 改简化或去碎片：重查简化等价、功能闭环、可见性转换、尺寸落点和复杂度。
- 改尺寸、文字、表格、标题栏、比例或图幅：重排整图并重做终评估。
- 仅补漏标：保持已有正确标注的编号、位置和样式，只增加缺失实体并同步清单；随后重做碰撞、回算、哈希、预览和连续闭环，不因局部补标强制删除后全部重标。
- 任何影响 DXF 的修改：重新导出、关闭源文档、回读、计算哈希、生成预览并重跑 A01～A11。

同一问题无法可靠关闭时停止自动修改，保留证据并请求设计输入；不得设置固定重试次数后强行通过。

## 6. 命令与状态

```powershell
python scripts/project_acceptance.py `
  --check <工程图检查记录.json> `
  --fit <图幅评估.json> `
  --performance <DXF性能审计.json> `
  --text-audit <DXF文字审计.json> `
  --stud-audit <压铆位置审计.json> `
  --preview <回读预览.png> `
  --output <项目验收记录.json>
```

连续复核应使用 FreeCAD Python 调用：

```powershell
<FreeCADPython> scripts/closed_loop_recheck.py `
  --step <当前源模型.step> --dxf <最终.dxf> `
  --check <工程图检查记录.json> --fit <图幅评估.json> `
  --preview <回读预览.png> --output-dir <连续复核目录> `
  --summary <连续复核汇总.json> --runs 3 `
  --hidden-color-aci 8 --dimension-color-aci 2
```

无颜色模板时使用上面的默认值；已确认模板采用其他图层颜色时，连续复核必须传入与单次性能审计相同的两个 ACI 值。

人工检查完成后才可传入 `--view-review`、`--drawing-review`、`--target-reader` 和 `--engineering-approval` 的 `pass/fail`。脚本退出码只反映图纸验收：`0` 图纸验收通过，`2` 需要返工，`3` 自动门禁通过但仍待输入或人工验收。工程批准单独写入 `production_release`，不混入图纸质量结论。

`overall_status`：

- `rework_required`：至少一项失败；
- `awaiting_required_input_or_manual_acceptance`：无失败但仍有待确认；
- `drawing_acceptance_passed`：除工程批准外的全部适用门禁通过。

`production_release` 独立取值：图纸未通过时为 `not_eligible`；图纸通过但工程批准待办时为 `pending`；批准拒绝为 `rejected`；仅企业授权批准后为 `released`。

报告用 `drawing_summary` 汇总除工程批准外的图纸门禁，用 `summary` 汇总全部项目；`closed_loop` 同时保存自动项完整性、当前 DXF 证据绑定、失败/待办编号、下一步动作和制图闭环完成状态。必须按 `next_action` 继续返工或关闭待办，不得把自动检查通过写成图纸完全合格。
